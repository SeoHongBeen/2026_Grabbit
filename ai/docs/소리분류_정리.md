## 0. 한눈에 보기

- **목표**: 실내 소리를 5종으로 분류 → RPi4에서 추론 → 위험 알림
- **클래스(5종)**: `crackling_fire, glass_breaking, siren, door_wood_knock, others` (인덱스 0~4)
- **핵심 우선순위**: **recall(놓치지 않기) > precision(오탐 줄이기)** — 알림 앱이라 진짜 소리를 놓치는 게 제일 위험
- **평가 방식**: **5-Fold 교차검증** — 모든 샘플을 test로 1번씩 → 소리 클래스 40개 전부로 평가 (믿을 수 있는 수치)
- **최종 성적(CV 종합, thr=0)**: 소리 4개 recall 평균 **0.84**, others 오탐 12%
- **운영 설정**: `OTHERS_KEEP=800` 모델 + 추론 임계값 **thr=0.6** → recall **0.76** / macro-precision **0.60** / 오탐 **6.7%**
- **배포 모델**: 전체 데이터로 학습한 `best_model.pth` (**101KB**, 가볍고 빠름 → RPi 유리)
- **precision-recall 한계선**: precision 0.7을 원하면 recall이 0.56으로 떨어짐(데이터 한계). 안전 앱이라 **recall 우선** 선택

## 1. 파일 구조

| 파일 | 역할 |

## 2. train.py 구조 — 2부 구성

```
데이터 로드 (map_label로 문자열→숫자)
  ├─ Part A. 5-Fold 교차검증  → 성능 추정 (발표용 신뢰 수치)
  └─ Part B. 전체 데이터 학습  → best_model.pth 저장 (배포용)
```

핵심 원칙: **언더샘플링·증강은 항상 train에만.** test(또는 fold의 검증 조각)는 실제 데이터 그대로 둬야 평가가 정직함(데이터 누수 방지).

### 공통 전처리 함수 (헬퍼)
| 함수 | 하는 일 | 왜 |
|---|---|---|
| `undersample_others()` | others를 400개만 랜덤 유지 | others가 1840개로 압도적 → 소리 클래스 주목도↑ |
| `augment_mfcc()` | 노이즈 + 시간마스킹 + 주파수마스킹 | MFCC 한 장에 변형 |
| `augment_minority()` | 소리 4개 클래스만 5배 증강 | 클래스당 원본 적음(40개) 보완 |
| `class_weights_tensor()` | 소리=4.0, others=1.0 | 소리 놓치면 4배 벌점 → recall↑ |
| `train_model()` | 새 모델 EPOCHS 학습 | 폴드마다 새로 학습 |
| `predict()` | 예측 라벨 리스트 반환 | 평가용 |

## 3. Part A — 5-Fold 교차검증 (제일 중요한 개념)

### k-fold가 뭐고 왜 쓰나
- 데이터를 **k조각(=5)** 으로 나눔
- 5번 반복: 매번 **1조각을 test, 나머지 4조각을 train** 으로 학습·평가
- 결과: **모든 샘플이 test로 딱 한 번씩** 쓰임 → 소리 클래스 **40개 전부**로 평가

### 왜 단일 split(8:2)보다 믿을 만한가
- 단일 8:2 → 소리 클래스 test **8개뿐** → 1개만 틀려도 12.5% 출렁, 운에 좌우됨
- 실제로 단일 split에선 siren이 1.00으로 보였지만, 40개로 재보니 **0.82**가 진짜값이었음
- **교훈**: 데이터 적을 땐 "한 번 나눠 재기"가 아니라 "여러 번 나눠 평균"이 정석
- 발표에서 "test 몇 개로 쟀냐" 질문의 방어 논리가 됨

### 코드 흐름 (폴드마다)
```
fold의 train/test 인덱스 받기
  → train에만 undersample_others + augment_minority   (test는 그대로!)
  → 새 모델 학습 (EPOCHS)
  → fold test 예측 → oof(out-of-fold) 예측 모음에 누적
5폴드 끝 → 누적된 전체 예측으로 classification_report + confusion_matrix
```
→ 이 종합 성적표가 **발표에 쓸 신뢰 수치**.

## 4. Part B — 최종 배포 모델

- 교차검증은 **성능을 추정**할 뿐, 배포할 모델을 만들진 않음
- 그래서 마지막에 **전체 데이터**로 모델을 한 번 더 학습 → `model/best_model.pth` 저장
- 데이터를 최대한 다 써서 학습한 게 실제 배포에 제일 좋음 (표준 관행)
- `test.py`는 이 `best_model.pth`를 불러 예측

## 5. CNN 구조 (cnn.py) — 왜 이렇게 짰나

### 바꾸기 전 문제
```python
fc1 = Linear(64*5*53, 128)   # 64*5*53 = 16,960 → 128 ≈ 217만 파라미터 (전체의 99%)
```
데이터가 적은데 파라미터가 너무 많음 → **통째로 외움(과적합)**

### 지금 구조 (BatchNorm + Dropout + GAP)
| 요소 | 역할 |
|---|---|
| **BatchNorm** (각 conv 뒤) | 학습 안정 + 약한 정규화 |
| **Global Average Pooling** | 거대한 fc1 제거 → 파라미터 217만 → 수천 개 (과적합 급감) |
| **Dropout(0.3)** | 학습 중 뉴런 일부 끔 → 외우기 방지 |

### 효과
- 뒤처지던 glass_breaking recall 끌어올려 **소리 4개 균형** 달성
- 모델 **8.7MB → 101KB** (86배↓) → RPi 추론 빠름
- GAP라서 **입력 길이 고정 불필요** → 슬라이딩 윈도우에 유리

### 교훈
> **데이터가 병목일 땐 모델을 "더 크게"가 아니라 "정규화"로 개선한다.**
> conv 더 쌓기/채널 늘리기 = 과적합 심화 = 역효과.

## 6. 실행 방법

```bash
# torch, librosa, scikit-learn, numpy 필요

# (MFCC 아직 안 만들었으면) 오디오 → MFCC
python toMFCC.py     # mfcc_features.npy, labels.npy 생성

# 교차검증 + 최종 모델 학습 (best_model.pth 저장)

# 단일 파일 예측 테스트
```

`train.py` 실행 시 출력 순서:
1. 폴드별 소리 recall
2. **교차검증 종합 성적표** (classification_report + confusion matrix) ← 발표용
3. 최종 모델 저장 완료 메시지

모델 6개(5폴드 + 최종 1) 학습이라 단일 split보다 시간 좀 더 걸림.

## 8. 성적표 읽는 법

```
                 precision    recall  f1-score   support
          siren       0.35      0.82      0.50        40
```
- **support** = 실제 정답 개수 (CV라 소리 클래스 40개 전부)
- **recall** = 실제 siren 중 맞춘 비율 = "얼마나 안 놓쳤나" ← **우리가 중시하는 값**
- **precision** = siren이라 예측한 것 중 진짜 비율 = "헛알림 여부"
- **f1** = 둘의 조화평균
- **confusion matrix**: 행=실제, 열=예측. 대각선=정답, 대각선 밖=어디로 틀렸나

읽기 순서: ① 소리 4개 **recall**이 고르게 높은가 → ② others 행에서 소리로 새는 **오탐** 몇 개인가
